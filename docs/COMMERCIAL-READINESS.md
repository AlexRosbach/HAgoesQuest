# Commercial readiness, licensing, and outstanding approvals

As of September 29, 2026. Preliminary technical and licensing assessment, not binding legal advice. This English translation preserves the historical assessment; it is not a new review of current terms.

## Assessment

Commercial distribution of an independent Quest app for controlling Home Assistant is possible in principle. **This development version is not yet a product ready for sale.** In particular, real multi-room localization, repeatedly reported hand-tracking issues, performance, the system keyboard, and camera presentation on Quest have not passed acceptance testing. Automated checks do not replace that acceptance.

## Unity: obtain written clarification before selling

The app controls a home and is therefore not exclusively a game or entertainment application. Under the definition considered in this assessment, it may qualify as an “Industry Customer” application; Unity determines the classification. Runtime distribution terms include an additional explicit authorization requirement for Industry customers. Do not rely solely on the Personal revenue threshold. Obtain written clarification from Unity on the classification, the actual plan used, the contract version applicable to the user, and the intended paid APK distribution. General Unity 6 rules provide for no Runtime Fee when conditions are met; that does not replace an appropriate license. Sources: [Editor Software Terms, sections 2.2/2.2.1 and definitions](https://unity.com/legal/editor-terms-of-service/software), [license eligibility](https://unity.com/pages/license-compliance), [FAQ](https://unity.com/legal/editor-terms-of-service/software/faq).

## Meta SDK and store

The installed Meta XR Core, Interaction, and MRUK packages refer to the Meta/Oculus SDK license. It permits application development and distribution subject to conditions, restricts use to approved platforms, and requires appropriate license/copyright notices. This is not blanket permission for all Meta examples: some separately licensed examples are intended only for noncommercial evaluation. This app uses original UI graphics and sounds; it does not incorporate film interfaces or separately downloaded Meta UI mockups.

A sideload build is not store approval. Publication requires a developer organization, compliance with store requirements/VRCs, privacy disclosures, and potentially review of requested camera permissions. Boundaryless remains an official platform feature; system safeguards and gestures are not bypassed. Sources: [SDK license](https://developers.meta.com/horizon/licenses/oculussdk/), [separate examples license](https://developers.meta.com/horizon/licenses/examples-license-1.0/), [VRCs](https://developers.meta.com/horizon/resources/publish-common-vrc-failures/), [permissions requiring review](https://developers.meta.com/horizon/resources/permissions-review-required/).

## Home Assistant and trademarks

The app communicates with a user-operated Home Assistant through the documented HTTP API. No Home Assistant server code is bundled in the APK. The separate API client therefore does not need to adopt the server's license solely because it connects to it. A server license does not grant trademark rights, however. Do not present “Home Assistant,” its logo, “Works with Home Assistant,” “Meta,” or “Quest” as your own brand or an official partnership. Review the product name “HA goes Quest” for trademark issues before commercial publication; clearly distinguish factual compatibility statements from certification badges. Sources: [HA REST API](https://developers.home-assistant.io/docs/api/rest/), [trademark information](https://www.home-assistant.io/tos/), [Works with compliance guide](https://works-with.home-assistant.io/resources/wwha-compliance-guide/).

## Included components and original content

- ZXing.Net: Apache-2.0; retain its license and existing notices. Newtonsoft.Json: MIT; retain copyright and license. Unity packages have their own Unity license terms and, in some cases, third-party notices.
- Local package license files and notices are supplied. Before sale, compare the actual release APK, including native libraries, against a component inventory again; this preliminary assessment is not a complete transitive legal review.
- New geometric icons and click sounds are generated by original app code. The existing fireball was generated; provenance and prompt are in `ART-MAGIC.md`. OpenAI's terms assign output rights as between the user and provider to the extent legally permitted, but do not promise uniqueness or freedom from third-party rights. [OpenAI terms](https://openai.com/policies/row-terms-of-use/).
- No Marvel/Iron Man branding, film music, or copied film interface is distributed. Following Meta's design guidance, the watch opens a stationary panel.
- An original public source-code license remains a decision for the rights holder. Third-party files must not be indiscriminately relicensed as original code.

## Required before sale

1. Clarify Unity classification and suitable commercial distribution rights; complete trademark and full component/license reviews.
2. Plan separate production signing with secure key management. The current APK deliberately uses the same development signature as earlier test versions to retain their tokens. Changing keys does not allow a normal update of the same installation; decide migration/store signing before the first sale.
3. Test cold starts in multiple rooms, recalibration, room changes, tracking loss, gestures, the system keyboard, extended sessions, and offline cases on a real Quest. Demonstrate measurable stability and performance.
4. Review privacy information and deletion procedures for access tokens, room anchors, camera and device data, and actual SDK processing. Do not broadly promise that no data leaves the device: Home Assistant requests intentionally go to the configured server, and platform services perform their own data processing.
5. Obtain legal review of pricing, support, update policy, store materials, and consumer/privacy information required in the distribution market.

**Conclusion:** Continue testing as an advanced prototype. Offer a paid consumer product only after these approvals and successful device acceptance.
